# FR-06 Reusable Phoneme-Listening Exercises Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract controlled identification/comparison views, integrate identification into the existing pilot, and add explicit safe replay without replacing its session or persistence machinery.

**Architecture:** Pure UI contracts and controlled widgets report actions to an owner. The existing discovery screen remains the real identification owner; a test-only comparison owner demonstrates the future interface without introducing comparison course progress. Two sequential reviewed tasks separate reusable presentation from pilot integration.

**Tech Stack:** Existing Dart/Flutter, Riverpod overrides, typed learning commands, FR-03 audio interfaces and deterministic widget/audio fakes; no dependencies added.

**Spec:** [Approved FR-06 design](../specs/2026-10-16-fr06-listening-exercises-design.md), published through [PR44](https://github.com/klottick/phoneme-app/pull/44), reviewed head `b409b6180dec70f4050068adfd80513ba828493c`, merge `508063883d5e1fc6534d0e7f62a6b3616d100ee4`.

## Global Constraints

- “Help learners distinguish French **phonemes**, including vowels and consonants, without turning a listening task into a spelling task.”
- “A component receives an immutable prompt and owner-supplied interaction state, and reports typed playback/answer requests.”
- “It never creates an audio engine, accesses providers or storage, computes a grade from spelling, or advances a session.”
- “FR-06 adds no subtype to the sealed `CourseExercise` catalogue, persisted action, codec variant, skill summary or production comparison route.”
- “Replay is available before submission, including after a successful listen.” Starting replay revokes that sample's permission; both comparison samples must succeed; only one playback active at a time.
- “A failed save retains the exact immutable command and existing recovery UI; never re-enable answering to reconstruct that command.” Preserve immediate owner feedback and ACK-only advancement.
- “The existing pilot's ten items, IDs, content revision, answer keys and saved session/storage formats remain unchanged.” Preserve FR-05 finite rounds, saved thresholds and mistake/history evidence.
- “Expose a supplied selection accurately when known.” Never guess a missing restored selection or add a persisted field for it.
- “Structural prompt validation is not linguistic validation.” Fixtures are authored declarations, not recording or curriculum approval.
- Preserve FR-03 source policy and exact `alphaAudioDisclosure`: `Alpha audio: recordings are unverified; device speech is practice-only.` No recording-failure TTS substitution.
- “Missing GitHub checks are not passing CI.” Preserve old data, Sound Match work, branches, worktrees and durable evidence; no automatic cleanup.
- No new assets, content registration, dependencies, backend/RPC, assessment, microphone, cloud evaluation, uploads, browser sandbox bypass or Qwen investigation; FR-15 remains deferred.

## Review Focus

1. Replay provider acquisition throws after an earlier success: revoke hearing **before** provider read, leave answers disabled, generic guidance, no evidence. Task2 `replay_provider_failure_revokes_prior_hearing`.
2. A/B reference IDs differ but target phonemes agree: Same is determined by the authored target relation, never reference/word equality. Task1 `comparison_uses_authored_phoneme_relation`.
3. Rapid activation before redraw: owner claims playback/submission synchronously; one active request/answer, no local widget grade or duplicate command. Tasks1/2 owner-guard tests.
4. A departed replay completes after another owner/prompt starts: neither hearing nor busy/selection/navigation may publish to the replacement; never stop its new playback. Tasks1/2 stale-replay tests.
5. Restored answered checkpoint has correctness but no selected choice: show feedback, no guessed selection/reanswer, no schema change. Task2 `restored_answer_does_not_invent_selected_choice`.

**Produces, test support:**

- `ControlledListeningAudio implements CourseReferenceAudio` exposes `List<ListeningPlaybackRequest> get requests`, `int stopCalls`, `int disposeCalls`. Both `speak` and `playReference` create held requests. `ListeningPlaybackRequest` exposes `String? spokenText`, `String? referenceId`, `bool settled`, `complete()`, `completeWith(CourseAudioResult result)`, `cancel()`, `fail({Object? cause})`. Default completed fake source is `CourseAudioSource.unverifiedRecording`; reference requests retain their requested ID. Bridge calls translate cancel/failure to existing typed exceptions. Stop/dispose count calls but intentionally permit an old held request to settle later for stale-result tests. Release all outstanding requests during test teardown.
- `ComparisonFixture({required SoundComparisonPrompt prompt, required String targetLocationA, required String targetLocationB, required String targetPhonemeA, required String targetPhonemeB, required PhonemeRelation expected})` is test-only. Reject blank target declarations or an expected relation inconsistent with the declared phoneme identities; do not claim acoustic/linguistic validation.
- `ComparisonHarness({Key? key, required ComparisonFixture fixture, required CourseReferenceAudio audio, required String ownerId, required ValueChanged<PhonemeRelation> onSubmitted})` is a test-only stateful owner/`WidgetsBindingObserver`. It owns heard slots, request generation, busy/playing, one submitted relation and feedback. Owner/audio replacement or changed fixture values (prompt ID/instruction/references, target locations/phonemes/expected relation) clear state; rebuilding equal values in new objects does not. Suspension clears playback permission. Capture the audio for each request/stop; never dispose injected players it does not own. `playReference` uses alphaPractice, normal, `allowPracticeTts: false`; only a completed matching-reference result grants hearing. Cancel is quiet; failures show `Audio unavailable. Try listening again.` without exception text. No progress/store imports or writes. Guard actions synchronously before awaits/redraws; the harness, not a hidden widget latch, owns exactly-once behavior.
