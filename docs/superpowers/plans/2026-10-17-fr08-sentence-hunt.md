> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

### Sentence package schema shared by Python and Dart

Use UTF-8 JSON, exact known field names, strict types, lowercase 64-character SHA-256 values and explicit UTC timestamps. No YAML, executable dataset code, implicit defaults for missing review/purpose or alternate field aliases. Task 1's serialized synthetic fixtures pin these field shapes; Task 3's Dart tests consume equivalent fixture JSON rather than inventing a second format.

| File/record | Required fields |
| --- | --- |
| `manifest.json` root | `schemaVersion:1`, `language:"fr"`, `courseId:"en-fr"`, `sections` (three ordered section records), `historicalSections` (initially empty, immutable older revision descriptors when revisions change) |
| Section record | `id`, `kind` (`vowels`/`consonants`/`mixed`), `title`, `contentRevision:1`, `policyRevision:1`, `completionThresholdPercent:80`, `items` (five ordered item records) |
| Item record | `id`, `sentenceId`, `audioRefId`, `purpose:"practice"`, `reviewState:"pending"|"reviewed"`, `targetSound`, `targetLabel`, `text`, `debriefNote`, `annotationRevision`, `annotationHash`, `tokens` (ordered `{id,text,phonemes}`), `expectedTokenIds` (authored order), `originalPath`, `clipPath`, `originalSha256`, `clipSha256` |
| `provenance.json` root/entry | `schemaVersion:1`, `entries`; entry has `itemId`, `source` (`repository`, `revision`, `config`, `split`, `rowId`, `audioPath`, `retrievalUrl`, `retrievedAt`, `rawTranscription`, `transcription`, `rawTsvRecord`), `original` and `clip` measurements (`path`, `sha256`, `byteLength`, `sampleRate`, `channels`, `sampleWidth`, `frameCount`, `durationSeconds`), `derivation` (`startFrame`, `endFrame`, `tool`, `version`, `settings`, `changes`, `transcriptCorrectionRationale`), `credit` (`creator`, `attribution`, `licenseId`, `licenseUrl`, `licenseTextPath`, `notices`, `evidenceIds`), `rightsReview` |
| `annotations.json` root/entry | `schemaVersion:1`, `entries`; entry has `itemId`, `annotationRevision`, `annotationHash`, `tool` (`name`, `version`, `settings`, `inputSha256`), `rawSentenceIpa`, `draftTokenPhonemes`, `corrections` (ordered `{tokenId,before,after,rationale}`), `frenchAudioReview` |
| Review record | `status` (`pending`/`accepted`/`rejected`), `reviewer`, `qualification`, `reviewedAt`, `originalSha256`, `clipSha256`, `annotationHash`, `evidenceIds`, `notes`; pending has null reviewer/qualification/date, no invented evidence; acceptance/rejection requires actual identified decisions matching the exact hashes |
| `source-evidence.json` root/entry | `schemaVersion:1`, `entries`; each has `id`, `url`, `retrievedAt`, `sha256`, `text` (archived source/notice evidence), `scope` (`dataset`/`tool`/`item`) and `itemIds` (empty for corpus/tool evidence); no opaque machine-local evidence paths |

`annotationHash` is the offline SHA-256 of canonical UTF-8 JSON of sentence/audio identity, exact text, annotation revision, ordered token IDs/text/phonemes and expected IDs (sorted object keys, compact separators, Unicode preserved). Review records are excluded so adding genuine review does not change the reviewed annotation itself. `sectionFingerprint` is the **canonical JSON string**, not a cryptographic digest, of ordered item content (including tokens/text/key), binary/annotation hashes and section content/policy identity. Use the same string canonicalization in Python/Dart fixtures, following existing command-fingerprint practice; no new Dart hashing dependency or home-grown cryptography. The offline verifier checks actual binary/annotation SHA-256; Dart checks hash-field/evidence agreement and computes the complete canonical section fingerprint so a changed key cannot resume an old checkpoint even with mistakenly unchanged metadata hashes. No timestamps/review-status-only changes alter scored content identity. Source/annotation hashes bind all qualifying evidence; neither tools nor runtime set reviewed status merely because those hashes match.
