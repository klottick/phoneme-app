# FR-07-A Discovery/Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete targeted teaching and primary entry for the existing discovery pilot while preserving saved progress and explicit legacy practice access.

**Architecture:** Add pure authored teaching metadata/validation, then a controlled debrief view consumed by the existing lesson owner. Home and progress use a small shared committed-completion projection; the real application router and existing audio/session/store remain authoritative. Three sequential PR gates separate pure content, lesson integration and navigation/progress integration.

**Tech Stack:** Existing Dart/Flutter, Riverpod, go_router, typed learning commands, transition-backed widget stores and controlled audio fakes; no new dependencies.

**Spec:** [Approved FR-07-A design](../specs/2026-10-16-fr07a-discovery-remediation-design.md), user approved after review of [PR49](https://github.com/klottick/phoneme-app/pull/49). ## Global Constraints

- “Completing A does **not** complete all of FR-07.” Production comparison remains FR-07-B with its own approved spec/plan; FR-15 remains deferred.
- “Do not change phoneme-wide interfaces into vowel-only contracts.” Live coverage remains the ten-item `/u/`–`/y/` pilot, not a full course.
- “The active exercise must not receive or expose targeted teaching notes.” No early-help, Word reference, explanation or answer-bearing semantics in first-pass/review puzzles.
- “A preserves the ten pilot items, authored order, answer keys, section/activity IDs, session aliases, scored content revision, saved policy and checkpoint/storage formats.” Any necessary incompatibility returns for user scope approval; no silent reset/revision bump.
- “Teaching notes are authored presentation metadata, not saved learner state.” No history dependency, persisted note text or guessed selected response.
- “Do not silently replace the configurable default-80% policy with 100% mastery.” Passing with unresolved mistakes retains optional review.
- “A failed save retains the exact pending command for explicit Retry saving, crediting once.” Immediate feedback stays; advance/review/Finish remain ACK-gated with owner/lifecycle fences.
- “Review-mode Finish still saves without adding a completion.” Audio failure/cancellation creates neither an answer nor a mistake.
- “Keep the legacy UI and audio/recording cleanup behavior intact.” No re-authoring/remapping of the other four lessons or import of old development data.
- Reuse existing `/u/`/`/y/` teaching only; no new phonetic claims/examples/keys. Structural validity is not qualified linguistic review.
- Preserve FR-03 disclosure/source rules, recording bytes/provenance/licences/root `LICENSE`, all old data, unpublished Sound Match work, branches, worktrees and process records. No recording-failure TTS substitution, grades, uploads, cloud evaluation, sandbox bypass or Qwen investigation.
- No product dependencies, new backend/RPC, new persisted kinds/codecs, assessment or full FR-11 navigation. External playback/AT, linguistic/audio/licensing, backend/privacy and release gates remain open; missing CI is not passing CI.

## Review Focus

1. Inconsistent teaching keys or unresolved aliases must not silently drop notes, guess content or change evidence. Task1 `teaching_rejects_ambiguous_bindings_and_unknown_aliases`.
2. Restored debrief with no retained history must still show the correct notes and saved threshold. Task2 `restored_debrief_needs_no_history`.
3. Invalid teaching on discovery entry must neither start/write a run nor prevent independent legacy access. Task2 `invalid_teaching_is_read_only_unavailable` plus Task3 real legacy routes.
4. Held/failed Finish or a departed account must not publish completion, exit twice or let Home show a draft pass. Task2 ownership regressions and Task3 `home_counts_only_acknowledged_finish`.
5. Duplicate, stale or legacy-one-pass records for the pilot must not manufacture discovery completion or inflate counts. Task3 `completion_projection_separates_discovery_from_existing`.
